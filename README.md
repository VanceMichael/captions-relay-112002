# 巡回展映多语字幕的逐场领用的演练来源

这里提供独立来源的本地合成记录，与实际单位、个人和线上业务无关。

## 本地运行

使用 Node.js 22.23.4。只使用 Node.js 自带的运行库。

执行 `npm test` 检查合成来源的接口。执行 `npm start` 启动来源，默认监听 `127.0.0.1:4100`，可通过环境变量 `PORT` 调整端口。访问根路径可看到来源名和当前回放阶段。

## 接口资料

| GET 路由 | 来源约定 |
| --- | --- |
| `/source/schedule` | cut 标识一版节目 timecode。语言顺序是场馆认可的首选和备用顺序。 |
| `/source/editing` | clips 中每项为片段身份、源起止毫秒、节目起点；区间左闭右开。 |
| `/source/captions` | from、to 为源毫秒；cutOnly 存在时使用该节目毫秒。splits 是译者同意的对齐分界，按该项给出的文本片段使用。 |

查询参数 `offset` 是从零开始的页偏移，`limit` 默认 3，取值 1 至 100。响应中的 `records` 含 `record` 来源记录键、`availableFrom` 首次出现的回放阶段、`kind` 记录类型、`payload` 业务字段。来源记录键与业务身份分别定义。`next` 为下一页偏移，末页为 `null`。回放阶段中的记录按到达顺序可查。

控制员通过 `POST /control?stage=2` 切换到第 2 阶段，服务会保留更早已可查的记录。每次换阶段后按根路径返回的 `stage` 确认切换成功。

## 逐场领用应用（`app/`）

应用层只使用 Node.js 自带运行库，按“来源客户端 → 目录状态 → 领域核验 → 领用编排”分层：

| 模块 | 职责 |
| --- | --- |
| `app/source-client.mjs` | 分页轮询三处来源、阶段切换、瞬断重试；每次同步完整重读，撤下与新到都以服务端现状为准。 |
| `app/catalog.mjs` | 归并到达记录：排期锁定节目版与语言、剪辑单整版替换、字幕累积撤下区间、许可登记；领用回执独立冻结，来源更新不改写已领包。 |
| `app/domain.mjs` | 逐“片段引用 × 语言 × 字幕子区间”核验，输出引用级状态与节目时码 cue。 |
| `app/relay-service.mjs` | 同步对账、领用冻结、回执回查、字幕/节目版/片段影响面审计。 |
| `app/relay-runner.mjs` | 逐阶段轮询的命令行入口，打印可领场次与阻塞明细。 |

### 核验口径

- **剪辑接点**：字幕与片段引用只是部分相交时，只有译者 `splits` 授权断开后的子区间能用于剪出两边；越界且未授权断开记 `uncuttable`，需请翻译补件，不整段送映。
- **撤下 vs 未到齐**：`withdraw` 命中的区间记 `withdrawn`；目录里完全没有覆盖的引用点记 `pending`，两类阻塞分开计数。
- **放映许可**：按场馆场次（`show`）与最终语言判定，grant 必须同时包含该场次与该语言；同一片段字幕可适用一场却不能发另一场。
- **备用语**：仅在排期 `languages` 的场馆认可顺序内补位，并保留自身语言标记；译稿自身 `publicDenied` 时该语言该段不可公开，备用语不能绕开同一段的公开限制。
- **cutOnly**：带 `cutOnly` 的字幕按节目毫秒判定，不随片段源起点平移，且只服务声明的节目版。
- **覆盖按引用计数**：`auditCaption` 对一份字幕在当前与历史节目版剪辑前后的每个引用分别给结论，不用文件数量表示覆盖。

引用级状态优先级：`public-denied` > `withdrawn` > `uncuttable` > `no-permission` > `pending`，内容级禁映/撤下不会被“需补件”掩盖，但所有命中的事实都会保留在 `blockers` 中。

### 运行与测试

- `npm test`：来源接口测试与 `app/` 下全部领域、端到端测试（共 13 项）。
- `npm run relay -- [baseUrl] [maxStage]`：启动来源后逐阶段轮询，输出每场可交付 cue 数与阻塞原因，并在结束时列出已冻结回执。
- 领用：`relay.claim(show, receipt)` 冻结当前评估；`relay.getReceipt(receipt)` 始终返回冻结时的旧时码包，排期里登记的 `pickup` 会在同步时自动冻结。
